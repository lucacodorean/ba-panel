# v1.0.0

- **Date**: 2026-11-26
- **Previous version**: v0.3.0

## Summary

This version makes the panel work in Laravel 13 and in Symfony 8.1 applications.
The package now has a framework-free core and two thin shells: one for Laravel and one for Symfony.
Both shells use the same plain PHP templates, the same validation, and the same feasibility agent.
You can now change the persona of the feasibility agent in an editable Markdown prompt file.
All package classes move to new namespaces. Code that imports a package class must change its `use` statements.

## Breaking changes

- All package classes move to new namespaces. **Action**: Update each `use` statement and each FQCN in your code. (BAP-008)
  - `Lucacodorean\BaPanel\BaPanelServiceProvider` becomes `Lucacodorean\BaPanel\Laravel\BaPanelServiceProvider`. Laravel package discovery registers the new class. If you registered the provider manually, replace the class name.
  - `Lucacodorean\BaPanel\Http\Controllers\PanelController` becomes `Lucacodorean\BaPanel\Laravel\Http\Controllers\PanelController`.
  - `Lucacodorean\BaPanel\Http\Controllers\FeasibilityController` becomes `Lucacodorean\BaPanel\Laravel\Http\Controllers\FeasibilityController`.
  - All other classes move to the `Core` namespace. `Lucacodorean\BaPanel\<Group>\<Class>` becomes `Lucacodorean\BaPanel\Core\<Group>\<Class>`. The groups are `Ai`, `Config`, `Exceptions`, `Graph`, `Markdown`, `Reports`, `Reports\Enums`, and `Search`.
  - Example: `Lucacodorean\BaPanel\Ai\FeasibilityAgent` becomes `Lucacodorean\BaPanel\Core\Ai\FeasibilityAgent`.
  - Example: `Lucacodorean\BaPanel\Reports\FeasibilityReport` becomes `Lucacodorean\BaPanel\Core\Reports\FeasibilityReport`.
- The package removes Blade. The templates are now plain PHP files: `resources/views/panel.php` and `resources/views/reports/feasibility.php`. The package ignores published `.blade.php` files. **Action**: If you published the views, run `php artisan vendor:publish --tag=ba-panel-views --force`. Copy your custom changes into the new `.php` templates. Replace the Blade echoes with PHP echoes, for example `{!! Md::cell($value) !!}` becomes `<?= Md::cell($value) ?>`. Then delete the old `.blade.php` files. (BAP-008)
- The Laravel view namespace `ba-panel` is removed. The view names `ba-panel::panel` and `ba-panel::reports.feasibility` do not exist. `FeasibilityReport::VIEW` changes from `ba-panel::reports.feasibility` to `reports/feasibility`. **Action**: Do not render the package views through the Laravel view factory. Use `Lucacodorean\BaPanel\Core\View\TemplateRenderer` with the template names `panel` and `reports/feasibility`. (BAP-008)
- `FeasibilityReport::toMarkdown()` changes its parameter. The old signature is `toMarkdown(Illuminate\Contracts\View\Factory $views)`. The new signature is `toMarkdown(TemplateRenderer $renderer)`. **Action**: Get `TemplateRenderer` from the container. Give it to `toMarkdown()`. (BAP-008)
- The `MAX_MESSAGE_LENGTH` and `MAX_CONTEXT_FILES` constants move from `FeasibilityController` to `Lucacodorean\BaPanel\Core\Feasibility\FeasibilityRequest`. The values do not change: 5,000 characters and 50 files. **Action**: Replace `FeasibilityController::MAX_MESSAGE_LENGTH` with `FeasibilityRequest::MAX_MESSAGE_LENGTH`. Replace `FeasibilityController::MAX_CONTEXT_FILES` with `FeasibilityRequest::MAX_CONTEXT_FILES`. (BAP-008)
- The `FeasibilityAgentFactory` constructor changes. The old constructor is `FeasibilityAgentFactory(ProviderFactory $providers, Repository $config)`. The new constructor is `FeasibilityAgentFactory(ProviderFactory $providers, AiSettings $settings, PromptLoader $prompts)`. **Action**: Get the factory from the container. If you extend the factory or create it with `new`, give the three new parameters. (BAP-008, BAP-009)
- The `FeasibilityAgent` constructor has a new second parameter `string $persona`. The new constructor is `FeasibilityAgent(AIProviderInterface $aiProvider, string $persona, ?string $workflowId = null)`. **Action**: Get the agent from `FeasibilityAgentFactory::make()`. If you create the agent with `new`, give the persona text as the second parameter. Give `$workflowId` as the third parameter or as a named argument. (BAP-009)
- The Laravel routes file moves from `routes/web.php` to `routes/laravel.php`. The paths and the route names do not change. **Action**: If you load or copy the package routes file, use the new path. (BAP-008)
- Composer does not install `illuminate/routing`, `illuminate/support`, and `illuminate/view` for the package. The Laravel packages are now in `suggest`. **Action**: A Laravel application already contains these packages. If your code uses `illuminate/view` only through this package, add it to your `composer.json`. (BAP-008)
- The feasibility endpoint returns `502`, not `500`, when the graph build or the report template fails. **Action**: If a client checks for `500`, also check for `502`. (BAP-008)

## Added

- Adds the Symfony shell `Lucacodorean\BaPanel\Symfony`. It contains `BaPanelBundle`, `Controller\PanelController`, `Controller\FeasibilityController`, and `Routing\BaPanelRouteLoader`. (BAP-008)
  - Register `Lucacodorean\BaPanel\Symfony\BaPanelBundle` in `config/bundles.php`.
  - Import the routes with `resource: '@BaPanelBundle/routes/symfony.yaml'`. The route names are `ba_panel`, `ba_panel_documents`, `ba_panel_search`, and `ba_panel_feasibility`. The paths are the same as in Laravel.
  - The bundle reads the same environment variables as the Laravel shell. You can set other values in `config/packages/ba_panel.yaml`. The keys are `enabled`, `ai.provider`, `ai.model`, `ai.key`, `ai.instructions_path`, and `docs`.
  - `docs` accepts a list of paths or one comma-separated string. A relative path resolves against `%kernel.project_dir%`.
  - The bundle validates the configuration in `BaPanelBundle::boot()` when the panel is enabled.
  - The bundle logs the `502` and `503` exceptions through `Psr\Log\LoggerInterface`. The response does not show the details.
  - When the request body is not a JSON object, the Symfony endpoint returns `422`.
- Adds the CSRF check of the Symfony shell. The header is `X-CSRF-Token`. The token id is `ba-panel`. (BAP-008)
  - The check is on when the `security.csrf.token_manager` service exists. Install `symfony/security-csrf` and enable `framework.csrf_protection`.
  - When the check is on, a request without a valid token gets a `403` response.
  - When the check is off, the panel page renders no token and the endpoint does no CSRF check.
- Adds the framework-free core services. (BAP-008)
  - `Core\Panel\PanelService` gives the graph, the documents, and the name search.
  - `Core\Feasibility\FeasibilityRequest` validates the feasibility request. It owns the limits and the error messages.
  - `Core\Feasibility\FeasibilityService::assess()` does the full flow of the endpoint. It returns `{report, markdown, html}`.
  - `Core\Config\AiSettings` holds the AI settings. `FeasibilityAgentFactory` gets them through its constructor.
  - `Core\View\PanelPage` holds the data of the panel page.
  - `Core\View\TemplateRenderer` renders the plain PHP templates.
  - `Core\Exceptions\InvalidTemplateException` reports a template name that is not valid or a template that does not exist.
- Adds template overrides for both shells. The host directory comes before the package directory. The first directory that contains the template wins. (BAP-008)
  - The Laravel host directory is `resources/views/vendor/ba-panel`.
  - The Symfony host directory is `templates/bundles/BaPanelBundle`.
  - Each template gets the `$e` helper to escape HTML and the `$js` helper to encode JSON for a `<script>` block.
  - The renderer refuses a template name with `..`, an absolute name, or a file extension.
- Adds the editable prompt file of the feasibility agent: `resources/prompts/feasibility.md`. It contains the role, the assessment rules, and the style of the agent. (BAP-009)
- Adds the configuration key `ai.instructions_path` and the environment variable `BAP_AI_INSTRUCTIONS_PATH`. The value is the path of the prompt file. The default is `null`. (BAP-009)
  - A relative path resolves against the application base path. Laravel uses `base_path()`. Symfony uses `%kernel.project_dir%`.
  - An absolute path is used as given.
  - A blank value is the same as no value.
- Adds the Laravel publish tag `ba-panel-prompts`. It copies the prompt file to `resources/prompts/vendor/ba-panel/feasibility.md`. When this file exists, the package uses it. You do not need a configuration value. (BAP-009)
- Adds the prompt file precedence. The first available step wins. (BAP-009)
  1. The configured path.
  2. Laravel only: the published copy `resources/prompts/vendor/ba-panel/feasibility.md`, when the file exists.
  3. The package prompt file `resources/prompts/feasibility.md`.
- Adds `Lucacodorean\BaPanel\Core\Ai\PromptLoader`. It selects the prompt file, reads it, and trims the text. (BAP-009)
- Adds `AiSettings::instructionsPath(): ?string`. It returns the configured path of the prompt file. It returns `null` for a null or blank value. (BAP-009)
- Adds the prompt file errors. When the selected prompt file is missing, not readable, or empty, the package throws `InvalidConfigurationException`. The message shows the resolved path. The feasibility endpoint then returns `503` with the message "The feasibility agent is not configured." The response does not show the path. (BAP-009)
- Adds the Symfony and the prompt file sections to `README.md`: the installation in Symfony, the Symfony configuration, the CSRF protection, the template overrides, the prompt customization, and the upgrade notes. (BAP-008, BAP-009)
- Adds Pest architecture rules to `tests/Unit/ArchitectureTest.php`. (BAP-008)
  - The core does not use `Illuminate`, `Psr\Log`, the Symfony framework components, or `Symfony\Bundle`.
  - The core does not use the Laravel shell or the Symfony shell.
  - The Laravel shell does not use the Symfony shell. The Symfony shell does not use Laravel or the Laravel shell.
  - `BaPanelBundle`, `BaPanelRouteLoader`, and `InvalidTemplateException` are not `readonly`. Their parent classes are not `readonly`.
- Adds tests for the Symfony bundle, the Symfony controllers, `AiSettings`, `FeasibilityRequest`, `FeasibilityService`, `PanelService`, `PanelPage`, `TemplateRenderer`, and `PromptLoader`. (BAP-008, BAP-009)

## Changed

- Changes the `require` list of `composer.json`. It contains only `php`, `composer-runtime-api`, `league/commonmark`, `neuron-core/neuron-ai`, and `symfony/yaml`. (BAP-008)
  - `illuminate/routing` and `illuminate/support` `^13.5` are in `suggest` for the Laravel shell.
  - `symfony/framework-bundle` `^8.1` is in `suggest` for the Symfony shell. `symfony/security-csrf` `^8.1` is in `suggest` for the CSRF check.
  - The `conflict` key refuses `illuminate/support` below 13.5 and `symfony/framework-bundle` below 8.1.
- Changes the system prompt of the feasibility agent. The prompt now has two blocks. The persona block comes from the prompt file. The contract block stays in code. (BAP-009)
  - The contract block always comes after the persona block. Thus the contract rules apply when the persona conflicts with them.
  - The contract rules are: use only the files of the request, write "Not specified in the documentation" for missing information and add an open question, give a verdict for each dimension and an overall verdict, use `needs_more_info` when the files do not give enough information, and list only the used file paths in the references.
  - The prompt file cannot remove or change the contract rules. The structured report keeps working.
  - The text of the package prompt file is the same as the persona part of the v0.3.0 prompt.
- Changes the Laravel container bindings. The container binds `AiSettings` and `FeasibilityAgentFactory` for each resolution, not one time. A change of the AI settings applies to the next agent. (BAP-008)
- Changes the panel page. It gets the URLs, the CSRF token, the CSRF header, the locale, and the limits from its shell. The page sends the CSRF header only when it has a token. (BAP-008)

## Removed

- Removes the Blade views `panel.blade.php` and `reports/feasibility.blade.php`. (BAP-008)
- Removes `illuminate/view` from the package dependencies. (BAP-008)
- Removes the classes in `Lucacodorean\BaPanel\Http\Controllers`. The Laravel controllers are now in `Lucacodorean\BaPanel\Laravel\Http\Controllers`. (BAP-008)

## Known limitations

- The endpoint does not stream. The request waits for the full report.
- Symfony reads `BAP_ENABLED` when it builds the container. After a change of `BAP_ENABLED`, run `php bin/console cache:clear`.
- The Symfony shell has no publish command and no automatic override location for the prompt file. Copy the file manually and set `ai.instructions_path`.
- The boot validation does not check the prompt file. A wrong path is visible only when the package builds the agent.
- A published copy of the prompt file does not get the changes of a later package version. Update the copy manually.
- Plain PHP templates do not escape values automatically. A template override must escape each value with `$e`, or send each report value through `MarkdownText`.

## Upgrade

1. Update the package with `composer require lucacodorean/ba-panel:^1.0.0`.
2. Update all `use` statements and FQCNs of package classes. Add `Core\` after `Lucacodorean\BaPanel\` for the core classes. Use `Lucacodorean\BaPanel\Laravel\` for the service provider and the controllers.
3. If you registered the service provider manually, use `Lucacodorean\BaPanel\Laravel\BaPanelServiceProvider`.
4. If you published the views, run `php artisan vendor:publish --tag=ba-panel-views --force`. Copy your custom changes into the `.php` templates. Delete the old `.blade.php` files.
5. If you call `FeasibilityReport::toMarkdown()`, give a `TemplateRenderer` from the container.
6. If you create or extend `FeasibilityAgentFactory` or `FeasibilityAgent`, give the new constructor parameters. Or get the classes from the container.
7. Optional: to change the agent persona in Laravel, run `php artisan vendor:publish --tag=ba-panel-prompts`. Then edit `resources/prompts/vendor/ba-panel/feasibility.md`.
8. Optional: to use another prompt file, set `BAP_AI_INSTRUCTIONS_PATH` in `.env`.
9. For a Symfony application, follow the "Installation in Symfony" section of `README.md`.
10. Open `/ba-panel` in the browser. Open a document, then open the feasibility agent and send a request.
